# Build Artifact

A build artifact is the output generated by the application build process.

Examples:

```text
Java
    app.jar

Node.js
    dist/

Python
    package/

Frontend
    build/

General
    application.zip
```

---

# CI/CD Flow

```text
Source Code
     |
     v
Checkout
     |
     v
Build
     |
     v
Package
     |
     v
Upload Artifact
     |
     v
Deploy
```

---

# Why Use Build Artifacts?

The application should normally be built once and then promoted through environments.

For example:

```text
Build Once
    |
    v
Artifact
    |
    +----> Dev
    |
    +----> QA
    |
    +----> Production
```

This is better than rebuilding the application separately for every environment.

---

# Example

Suppose the build creates:

```text
build/
└── product-service.txt
```

The workflow uploads it:

```yaml
- name: Upload build artifact
  uses: actions/upload-artifact@v4
  with:
    name: product-service-build
    path: build/
```

# Real-Time DevOps Concept

A mature CI/CD pipeline often follows:

```text
Developer
    |
    v
Git Push
    |
    v
CI
    |
    +-- Build
    +-- Test
    +-- Security Scan
    |
    v
Build Artifact
    |
    v
CD
    |
    +-- Dev
    +-- QA
    +-- Production
```

The artifact becomes the output of CI and the input to CD.

---

# Important Principle

> Build once, deploy the same artifact across environments.

This helps ensure that the artifact tested in CI is the same artifact deployed to production.
